## Known issues and tech debt

### Security
- **JWT is stored in `localStorage`**, so any XSS can read it. Consider an
  httpOnly cookie plus CSRF protection when the backend is re-hosted.
- **Logout does not revoke tokens.** JWTs are stateless and valid for 7 days
  (`jwt_expires_days`). Add a denylist or short-lived tokens plus refresh
  tokens if that matters.
- `SessionMiddleware` (OAuth state only) reuses `JWT_SECRET` as its key.
  A separate secret would be cleaner.

### Correctness and product
- **Challenges have no server catalog.** XP is capped at 50 per challenge and
  at 10 challenges per module (`backend/app/catalog.py`). This is a stopgap:
  the real fix is shipping challenge definitions and deriving XP server-side,
  as is already done for modules via `backend/app/data/modules.json`.
- `modules.json` is generated by `backend/scripts/gen_catalog.py` and must be
  regenerated whenever topics change. Nothing in CI checks that it is fresh
  (a cheap check would be to run the script and fail on `git diff`).
- Since #86, the backend rejects modules missing from the catalog (404). If
  the catalog is stale, completions of new modules are silently dropped from
  the client's sync queue.

### Tests and tooling
- **e2e (Playwright) does not run in CI**, and `frontend/e2e/auth.spec.ts`
  ("handles OAuth callback") is stale: it passes `?code=` without `state`,
  while the callback now reads the URL fragment.
- Unmet peer dependency: `@nuxt/test-utils@4` wants `jsdom >= 27.4`, but
  26.x is installed.
- **TypeScript 7 is blocked**: vue-tsc (3.3.11 at the time) needs the JS API
  that TS 7 dropped (`ERR_PACKAGE_PATH_NOT_EXPORTED ./lib/tsc`). TS majors
  are ignored in `.github/dependabot.yml`. Revisit when vue-tsc supports TS 7.
- pnpm enforces `minimumReleaseAge`: very fresh dependabot versions fail CI
  with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`. Wait a day and re-run.
  Nothing is broken in that case.
- The transitive security `overrides` in `pnpm-workspace.yaml` should be
  removed once the parent packages ship the fixed versions.

### Housekeeping
- `frontend/public/mockServiceWorker.js` is shipped in the production build.
  It is harmless because MSW only starts in dev (`plugins/msw.client.ts`),
  but it could be excluded from the build.
- Some code comments are in Russian; the project rule is English only.
- `docs/AGENTS.md` asks for `.env.example` files, but they are listed in
  `.gitignore`. Decide which one is right.
- `docs/MIGRATION.md` Phase 0–1 are done, but the checkboxes are only
  partially updated.

## Decisions log

| Date | Decision | Why |
| --- | --- | --- |
| 2026-07-08 | Backend before the Nuxt migration | The frontend was already API-ready, and Nuxt would have churned it for little value. |
| 2026-07-10 | Nuxt 4 in SPA mode first, SSG later | Hosting is static (Pages); full SSR needs Node hosting. |
| 2026-07 | Custom `codeql.yml`; CodeQL default setup stays **off** | Both at once cause conflicting uploads. |
| 2026-09-29 | Server catalog is the only source of module XP; unknown modules → 404 | Client-sent XP and slugs are untrusted (XP farming, unbounded JSONB). |
| 2026-09-29 | `users.email` is not unique | The same person can use several providers, and Twitch/Discord can return no email. |
| 2026-09-29 | The OAuth callback passes the token in the URL fragment | Keeps the JWT out of server logs and `Referer`. |
| 2026-09-29 | Dependabot monthly and grouped; TS majors ignored | The project is frozen, so there is less PR noise. |
| 2026-09-29 | Railway dropped; the future backend is a self-run Docker service | The trial ended. |
